# Recording and review workflow

**No recordings are currently supplied or approved.** The central manifest is generated in `src/audio.ts`: one unique entry per short and long sound, upper/lower letter name, teaching word, and vowel-comparison word. All entries default to `NOT_RECORDED`. Glottal stop is deliberately deferred.

1. Use `teacher-review/audio-recording-script.csv` as the complete script. A fluent Somaliland Somali speaker should record the actual sound (not an English letter name), each whole word, and both members of each comparison. Letter-name recordings are optional and separate from sound recordings. Document legitimate regional variation rather than labelling it an error.
2. Capture clean, consistent, uncompressed mono WAV masters at 44.1 or 48 kHz, 16-bit or higher; no music or noise reduction artefacts. Export consistent MP3 files at the exact manifest paths. Check onset, end, clipping and audible silence. Maintain secure masters separately.
3. Obtain speaker consent, licensing and recording metadata. A competent independent Somali reviewer should evaluate pronunciation and curriculum context; record reviewer, date and evidence. Store only permissioned metadata, not sensitive personal information.
4. Add the actual files beneath `public/audio/`, preserving manifest paths. Update the corresponding `recordingAudit` record in `src/audio.ts` with the factual speaker, dialect, licence, consent reference, recording date, reviewer, review date and review evidence, and set status, reviewStatus and pronunciationStatus to `APPROVED` **only after actual approval**. Use `RECORDED`, `AWAITING_REVIEW` or `REJECTED` as appropriate before then. Never invent approval.
5. Run the tests and manually verify every recording, including special consonants, long vowels and word pairs. Audio is unavailable unless all three statuses and required metadata indicate approval **and** the file is actually served as audio. No learner score is assigned to unavailable listening content.
